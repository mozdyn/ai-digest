V100/Qwen3.8: crash multi-GPU nadal występuje po #29803

Co się zmieniło: issue #29562 dostało świeży produkcyjny update: runtime zawierający #29803 nadal crashuje deterministycznie na 6× Tesla V100 32 GB / GV100 z Qwen3.8-Flash-Next Q8_0/Q6_K. Są też dwa nowe crashe z normalnego ruchu agentowego przy wysokim prefix-cache reuse: jeden kilka sekund po rozpoczęciu partial-reuse prefill, drugi dokładnie na granicy prefill→decode.

Dlaczego ma znaczenie: #29803 naprawił realne konfiguracje Volta Flash Attention, ale nie ten konkretny qwen4exp crash. Nowe dane wskazują bardziej na indexer/sparse-attention albo shape-dependent kernel launch niż na samą tabelę FA.

V100/SM70: bezpośredni reproducer: 6× Tesla V100-class, layer split, main GPU GV100/sm_70, CUDA 12.4, ctx ~262K, F16 KV. Q8_0 i Q6_K padają w tym samym miejscu.

Qwen3.6/Qwen3.8: bezpośrednio Qwen3.8-Flash-Next/qwen4exp; Qwen3.6 nie jest reproduktorem.

NInfer przebudowuje scheduler: preemption Snapshot/Replay, 1–8 lanes, shared KV i nowe TTFT/Prometheus

Co się zmieniło: upstream NInfer zastąpił stary context-cache planner nowym resource ownership + preemptive scheduling. Runtime ma 1–8 resident execution lanes, resource-pressure preemption, Snapshot/Replay recovery, shared Device KV i wspólny pinned Host budget. Kolejne commity redukują preparation/context overhead, dodają TTFT/recovery campaign, Prometheus metrics i naprawiają cache-boundary markers gubione przez Jinja trim.

Dlaczego ma znaczenie: to duża zmiana w parallel sessions, host cache, recovery i server scheduling. Autor podaje, że zwykłe 55K warm requests poprawiły się; w campaignie 224 first-output observations było szybszych, 83 wolniejszych. Cold256 i heavy-media regressions pozostają.

llama.cpp: Qwen3.8 k-pool graph reallocation fix dla shared KV / multi-seq
