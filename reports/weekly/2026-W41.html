Rekomendacje tygodnia

Stabilność przed „auto”

Na V100 przypnij CUDA 12.x i wersję runtime. Zmierz Strata CPU-share on/off, TOP_K i MMQ correctness. Nowsze nie znaczy szybsze ani bezbłędne.

Eksperci + memory budget

Jeśli model przekracza 32 GB, sprawdź merged llama.cpp GPU LRU. Zapisuj resident layer count, hit/miss ratio, VRAM peak, PCIe H→D i PP/TG, nie tylko tok/s.

KV i adapter identity

Na dynamicznym LoRA wyłącz --cache-ram do czasu fixu #30129. Zweryfikuj save/restore slotów, długi prefiks i Qwen3.8 MTP state po rollbacku.

NInfer — artefakty i logi

Oddziel upstream od ninfer-v100; wsparcie artifact v3 nadal otwarte. W benchmarkach zapisuj commit, CUDA, artifact SHA, context length, cache hits i accepted tokens/round.

Hermes hardening

Po snapshotcie state.db/WAL wdrażaj v0.21.6 tam, gdzie używasz gateway. Sprawdź security defaults i pamiętaj, że Desktop/Termux nie dostały jeszcze tego samego bundla.

Gateway z limitami

OpenViking 0.5.0 testuj na localhost, write tools domyślnie wyłączone; ustaw maks. rundy/czas/tokens w hidden tool loop i porównaj prompt-cache reuse.

3 rzeczy do przetestowania w homelabie

1 · MoE LRU na single V100

Duży Qwen3.8 MoE z ekspertami częściowo w RAM. Porównaj --moe-cache-mib 0/2048/4096/6144, --fit, kontekst 4K/32K, PP i TG. Mierz PCIe transfer, cache hit i peak VRAM. Nie używaj małego MoE mieszczącego się w całości w VRAM jako testu offloadu.

2 · KV/LoRA correctness

Qwen3.6 lub Qwen3.8, dwa prompty P/Q, LoRA scale 0→1 i --cache-ram 0 jako golden. Dodaj slot save → restore i długi prefiks. Wymagaj identycznego outputu i braku re-prefill, nie tylko braku crasha.

3 · ninfer-v100 kontra upstream

Przypięte CUDA 12.8, sm70, dwa wydania tego samego artefaktu jeśli dostępne. Zapisz build issue #17, v2/v3 load status, TG/PP @2K/32K/128K, TTFT, RAM/VRAM i decode acceptance. Brak porównywalnych wag lub artifacts oznacz jako „brak miarodajnego A/B”.

Trend tygodnia

Cache staje się częścią algorytmu — i częścią poprawności.

W tygodniu widać przejście od „może trochę przyspieszyć kernel” do decyzji gdzie mieszkają eksperci, jakie KV jest przypisane do LoRA, co zostaje po save/restore i czy agent naprawdę może wznowić rozmowę. GPU LRU MoE potrafi przyspieszyć nowsze karty niemal dwukrotnie, ale Strata pokazuje, że ten sam ogólny pomysł optymalizacji host↔GPU może być stratą na V100 z resident experts. Z kolei OpenViking Gateway przenosi pamięć z osobnego pluginu do warstwy API, zwiększając wagę ACL, terminów i limitów narzędzi.

Single V100 32 GB PCIe nie ma dziś jednego „zwycięskiego silnika”. Różnica między llama.cpp, NInfer forkami i Strata jest mniej ważna niż powtarzalny model, stabilny artifact, poprawny KV i dokładny profil cache miss. Stare GPU wymaga osobnego hardwarowego benchmarku.
